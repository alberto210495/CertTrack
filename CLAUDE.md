# CertTrack

A C# (.NET 10) study tracker for CompTIA exam objectives. This is a portfolio project for GitHub, built by a software engineering student who is studying for CompTIA A+ first, then Network+ and Security+.

## Goal

A full-stack CRUD app with auth, tests and CI. "A boring idea done well beats a clever one done badly."

- JWT or session auth
- Input validation
- Unit tests
- A GitHub Actions pipeline

The command-line app was the first stage. The web app reuses its model and logic.

## How to work with me on this

- This is a learning project. Guide and review rather than writing whole features unprompted. Write code only when asked.
- Be direct. Point out mistakes explicitly and suggest better approaches.
- Keep answers short and scannable.
- One commit per build step, with clear commit messages.

## Current state

- Every item of the goal is built: CRUD, JWT auth, validation, tests and a CI workflow.
- The CLI works: `add`, `list`, `study`, `done`, `stats`, `help`, with colored output and friendly errors.
- The web app works: register, login, and add, edit, delete, filter and stats for objectives, each user seeing only their own.
- 90 xUnit tests pass: 44 for Core and the CLI, 46 for the API.
- The CI workflow has not been seen running on GitHub yet. Check the Actions tab after the next push.
- The repo is on GitHub at https://github.com/alberto210495/CertTrack, branch `main`.

## Decisions made

- JWT, not sessions, because it can be tested without a browser.
- The signing key comes from `Jwt:Key` (environment variable `Jwt__Key`, at least 32 characters). In Development an unset key becomes a random key for that run. Anywhere else the app refuses to start without it.
- `UserObjective` inherits from Core's `Objective`, so the CLI's JSON has no owner field.
- Another user's objective returns 404, not 403.
- NuGet packages for ASP.NET Core and EF Core are pinned to 10.0.15. The latest on NuGet is 11.0.0, which does not work with .NET 10, so `dotnet add package` needs `--version 10.0.15`.
- The front end is plain HTML and JavaScript with no build step. It writes user text with `textContent`, never `innerHTML`.
- API tests use `WebApplicationFactory` with one in-memory SQLite database per test.

## Not done

- No HTTPS redirect, login attempt limit, password reset or account deletion.
- The CLI has no delete or edit, and does not share data with the web app.
- The web page has no automated tests.

## Notes

- `objectives.json` is the CLI's local data and is in `.gitignore`. It is written to the folder the command is run from.
- `src/CertTrack.Api/certtrack.db` is the web app's local data. `*.db` files are in `.gitignore`.
- Never commit secrets. `Jwt:Key` must not be written into `appsettings.json`.
- Keep `docs/DOCUMENTATION.md` in sync when commands or files change.
- After changing a model class, add a migration and rebuild before running. Running old binaries against a new migration fails with "no such table".
- Windows Smart App Control was turned off on this machine because it blocked freshly built DLLs with error `0x800711C7` ("An Application Control policy has blocked this file"). If that error comes back, Smart App Control is the cause.
- The GitHub CLI (`gh`) is not installed. Repos are created on the GitHub website.
